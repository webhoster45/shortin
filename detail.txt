[1] (https://medium.com/me-n-stack-development/15-minutes-to-understand-url-shortener-system-design-27268013bd25), [2] (https://www.freecodecamp.org/news/build-a-scalable-url-shortener-with-distributed-caching-using-redis/), [3] (https://upstash.com/docs/redis/tutorials/python_url_shortener), [4] (https://oneuptime.com/blog/post/2026-03-31-redis-how-to-build-a-url-shortener-with-redis/view)Important Redis CommandsSET key value EX seconds: Stores a key-value pair and sets a time-to-live (TTL) in seconds.GET key: Retrieves the original long URL.INCR key / HINCRBY key field increment: Atomically increases the click counter or metadata metric.EXPIRE key seconds: Sets or updates the expiration time on an existing key.TTL key: Checks how many seconds remain before a short link expires. Save short_code -> long_url in Redis with an optional TTL using SET. [1] (https://upstash.com/docs/redis/tutorials/python_url_shortener), [2] (https://oneuptime.com/blog/post/2026-03-31-redis-how-to-build-a-url-shortener-with-redis/view), [3] (https://www.freecodecamp.org/news/build-a-scalable-url-shortener-with-distributed-caching-using-redis/)Rate Limiting: Before processing, check a key like rate:ip:<user_ip>. If it exceeds your threshold, reject the request. Otherwise, run INCR with a 60-second EXPIRE if it's new.Redirect & Count Clicks: When a user visits the short link, fetch the long URL via GET. Run INCR on a separate counter key like clicks:<short_code> to track usage without slowing down the redirect. Issue an HTTP 302 Found redirect to the long URL.
